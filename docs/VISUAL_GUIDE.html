Link Preview Card

Paste a URL, get a real preview card stored as plain note text. This dashboard explains the promise, the module map, the note format, and the rules that must survive future edits.

What it is for

The short version a new maintainer needs before touching code.

Paste and move on

A single URL on an empty line becomes a finished card in about a second, with no dialog and no configuration.

Live in plain text

Each card is a ~~~link-preview fenced block, so it syncs with the vault and survives uninstalling the plugin.

Privacy by default

UTM tags, click IDs, and share tokens are stripped before a URL is fetched, stored, copied, or converted.

Reversible everywhere

Any card turns back into its link in one click, and every card edit is a normal note edit with undo.

Bulk without fear

The link manager converts selected rows only, rescans before writing, and splices bottom-up so line numbers stay valid.

Looks intentional

Three layouts, two media sides, three radii, and two placeholder styles; a card without an image still looks designed.

Four pure modules behind the UI; all host access goes through Obsidian APIs.

Feature contract

If a change breaks one of these, it is a regression, not a refactor.

Paste guard

Auto-convert only when: setting on, no selection, exactly one URL, blank cursor line, outside any fence.

Failure restore

A failed fetch puts the original pasted text back and says so; it never leaves an empty card.

Editor-first edits

Card changes go through the live editor when the note is open, else flush and process the file.

Bottom-up bulk

Multi-row conversion sorts by line descending before splicing, so offsets never shift under it.

Image lock

Manual image sets imageLocked; Refresh updates text but keeps the chosen image.

Bounded fetches

Three concurrent metadata requests, 10-second timeout each, progress after every completion.

No double open

Action buttons stop propagation; the card-level click opens the link only from non-interactive areas.

Malformed safety

Invalid JSON or a non-HTTP URL renders as raw text; window.open only runs on parsed URLs.

Decisions worth knowing

Each one replaced a specific failure.

Chosen

Markdown as database

Cards travel with the note. A path-keyed store would orphan cards on rename and lose everything on uninstall.

Chosen

Tilde fences

~~~ avoids collisions with the backtick fences used everywhere else in notes.

Chosen

Id then URL

Two cards for one URL stay independent because edits match the stored id first.

Chosen

Rescan at write time

Bulk targets are re-matched against fresh text; vanished links are skipped instead of mis-replaced.

Chosen

Defaults at render

data.layout || settings.layout applies new preferences to old cards without rewriting notes.

Chosen

Picker delegation

Use Note Toolbox's browser when available, then its generic picker, then the built-in fuzzy list.

Landmines

The failures that look like small cleanups until they corrupt a note.

Trap

CRLF notes

Detect \r\n once per write; joining with \n rewrites every line of a Windows note.

Trap

Empty values

serialize drops empty strings; that is how "remove image" clears the field.

Trap

Shallow settings merge

visibleActions needs its own nested merge, or new toggles vanish for existing users.

Trap

Inline URLs

Only whole-line links are convertible; URLs in prose stay informational.

Trap

Click bubbling

Without the button/anchor guard, every toolbar action also opens a browser tab.

Trap

No request timeout

requestUrl never times out on its own; the 10-second race is load-bearing.

Trap

Vault image paths

Raw paths in <img src> break; resolve through getResourcePath.

Trap

runtime/ drift

The frozen bundle is the user's rollback. Never build into it.
